## ⚠️ اول این را بخوانید

SST یک **شل واقعی root روی سرور شما** را به یک چت تلگرام وصل می‌کند. یعنی:

> **هر کسی که اکانت تلگرام شما را در اختیار بگیرد، سرور شما را در اختیار گرفته.**

قبل از نصب:

- ✅ در تلگرام **تأیید دو مرحله‌ای** را روشن کنید (Settings → Privacy and Security)
- ✅ برای سرورهایی که واقعاً برایتان مهم‌اند، از SSH با کلید استفاده کنید
- ✅ فایل `config.json` را هیچ‌وقت کپی، پیست یا آپلود نکنید - توکن ربات و کلید مخفی وب‌هوک داخلش است
- ✅ بدانید که چت‌های ربات در تلگرام **رمزنگاری سرتاسری ندارند** (بخش [امنیت](#-امنیت))

این ابزار برای راحتی است، نه جایگزین SSH سفت‌شده.

- 📱 **مینی‌اپ** - ترمینال کامل و مرورگر فایل داخل خود تلگرام

## 🚀 نصب

```bash
bash <(curl -Ls https://raw.githubusercontent.com/AssA7778/SST/main/setup.sh)
```

> نیاز به دسترسی **root** دارد.

نصب‌کننده توکن ربات، آیدی عددی و حالت اتصال را می‌پرسد و بقیه را خودش انجام می‌دهد: ساخت کلیدهای مخفی، گرفتن گواهی TLS، ساخت سرویس systemd و ثبت وب‌هوک.

| چه چیزی لازم است | از کجا |
|---|---|
| توکن ربات | [@BotFather](https://t.me/BotFather) → `/newbot` |
| آیدی عددی شما | [@userinfobot](https://t.me/userinfobot) |

### انتخاب حالت

| | Webhook | Polling |
|---|---|---|
| سرعت | آنی | حدود ۱ ثانیه تأخیر |
| دامنه لازم است؟ | ✅ بله | ❌ خیر |
| پورت باز لازم است؟ | ✅ بله (۸۸ یا ۴۴۳) | ❌ خیر |
| سطح حمله | یک پورت باز روی اینترنت | **هیچ** - فقط ارتباط خروجی |

> 💡 **اگر دامنه ندارید یا شک دارید، Polling را انتخاب کنید.** حدود یک ثانیه کندتر است ولی هیچ پورتی باز نمی‌کند و از نظر امنیتی گزینهٔ محافظه‌کارانه‌تری است.

برای حالت Webhook اول یک رکورد DNS بسازید:

```
Type: A     Name: bot     Value: <آی‌پی سرور>     TTL: auto
```

> کاربران Cloudflare: حتماً روی **DNS only** (ابر خاکستری) بگذارید. با پروکسی روشن، تلگرام نمی‌تواند به پورت ۸۸ برسد.

## 🎮 دستورات

در چت `/` را تایپ کنید تا فهرست کامل ظاهر شود. دستورات در تلگرام ثبت شده‌اند
ولی فقط برای چت خودتان؛ هر کس دیگری که ربات را پیدا کند چیزی نمی‌بیند.

دکمهٔ کنار کادر پیام، **مینی‌اپ Terminal** است نه منوی دستورات، پس اپ همیشه با
یک ضربه باز می‌شود.

**ربات فارسی حرف می‌زند.** توضیح دستورها، راهنمای `/start`، خط وضعیت و پیام‌های
خطا همه فارسی‌اند؛ خروجی خود ترمینال طبیعتاً دست‌نخورده می‌ماند. راهنماها به‌جای
بلوک تک‌فاصله به‌صورت متن معمولی فرستاده می‌شوند تا تلگرام درست راست‌به‌چپشان کند،
و توکن‌های لاتین مثل `/full` علامت‌گذاری شده‌اند تا وسط جملهٔ فارسی جابه‌جا نشوند.

| دستور | کار |
|---|---|
| `/start` | باز کردن (یا نمایش) سشن شل |
| `/new` | بستن شل و ساخت یک شل تازه |
| `/close` | بستن سشن |
| `/app` | باز کردن مینی‌اپ ترمینال |
| `/status` | وضعیت سرور و سشن (لود، رم، آپتایم) |
| `/full` | ارسال کل خروجی به‌صورت فایل `.txt` |
| `/clear` | پاک کردن صفحه |
| `/key <name>` | ارسال کلید خام: `up` `down` `left` `right` `esc` `tab` `enter` `sigint` `sigtstp` `eof` `clear` |
| `/help` | راهنما |
| **هر متن دیگر** | روی سرور اجرا می‌شود |

### دکمه‌ها

دو ردیف فلش، و شکلشان می‌گوید کدام کدام است: **فلش باریک تایپ می‌کند، فلش
صفحه‌ای اسکرول می‌کند.**

| دکمه | کار |
|---|---|
| ↵ ⛔ ⇥ | Enter، Ctrl+C، Tab |
| ↑ ↓ | تاریخچهٔ دستورات شل (همان کلیدهای فلش واقعی) |
| 🔼 🔽 | اسکرول عقب و جلو در خروجی‌های قبلی |
| ⟳ | تازه‌سازی صفحه، برای دستورهای طولانی |
| ⌧ | پاک کردن |
| 📄 File | فرستادن کل خروجی به‌صورت فایل |

با زدن 🔼 پیام به نمای اسکرول می‌رود با ⏫ 🔼 🔽 ⏬ و ⤓ Live. آنجا کلیدهای شل
اصلاً وجود ندارند، پس یک ضربهٔ اسکرول هیچ‌وقت به شل نمی‌رسد. هر دستوری که تایپ
کنید بلافاصله به نمای زنده برمی‌گردد. Ctrl+Z و Ctrl+D زیر `/key` هستند.

هر پیام تلگرام ۵۵ خط جا می‌دهد و scrollback تا ۴۰۰۰ خط نگه می‌دارد. برای
خروجی‌های بلندتر از این، `/full` یا مینی‌اپ ابزار بهتری است.

## 📱 مینی‌اپ

با `/app` یک ترمینال کامل داخل تلگرام باز می‌شود: بدون محدودیت ۴۰۹۶ کاراکتر،
بدون ویرایش پیام، با اسکرول واقعی و یک مرورگر فایل در کنارش. **همان سشن شلِ**
چت را کنترل می‌کند، پس می‌توانید دستوری را در یکی شروع کنید و در دیگری تماشا
کنید.

| تب | کارکرد |
|---|---|
| **TERMINAL** | صفحهٔ زنده روی WebSocket، با نوار کلید ^C، Tab، Esc، فلش‌ها، ^Z، ^D، ^L |
| **FILES** | گشتن در هر پوشه، پیش‌نمایش فایل متنی، دانلود، و مسیر breadcrumb |

صفحه در سمت سرور رندر می‌شود و فقط متنش استریم می‌شود، پس نه xterm.js لازم است
نه هیچ CDN ای - کل صفحه یک فایل مستقل است. این روی شبکه‌هایی که CDNها کند یا
بلاک‌اند اهمیت دارد.

**پیش‌نیازها:** حالت webhook، یک دامنه، و گواهی معتبر از یک CA. مرورگر داخلی
تلگرام گواهی self-signed را قبول نمی‌کند، پس دکمه فقط وقتی ظاهر می‌شود که
واقعاً کار کند. اگر نشد، `/app` دلیلش را می‌گوید.

احراز هویت با `initData` امضاشدهٔ تلگرام است: پیام با HMAC-SHA256 و کلیدی که از
توکن ربات مشتق می‌شود امضا شده، و SST امضا، آیدی کاربر و تاریخ آن را چک می‌کند
و بعد یک توکن کوتاه‌مدت می‌دهد. `/app` یک لینک مرورگر معمولی هم می‌دهد که با
کلید جداگانه‌ای محافظت می‌شود، برای وقتی که ترمینال را روی لپ‌تاپ می‌خواهید.

## 🔒 امنیت

### داده‌های شما از کجا عبور می‌کنند

```
   گوشی شما
       │  MTProto  (رمزنگاری کلاینت↔سرور تلگرام)
       ▼
 سرورهای تلگرام  ←── می‌توانند دستورات و خروجی شما را بخوانند
       │
       ├─ حالت webhook:  TLS 1.2+  ──►  سرور شما :88
       │
       └─ حالت polling:  سرور شما  ──TLS 1.2+──►  api.telegram.org
                         (گواهی و نام دامنه تأیید می‌شود)
```

**چت‌های ربات رمزنگاری سرتاسری ندارند.** قابلیت Secret Chat تلگرام شامل ربات‌ها نمی‌شود، پس هر دستوری که تایپ می‌کنید و هر بایت خروجی، به شکل قابل خواندن از سرورهای تلگرام عبور می‌کند. این نحوهٔ کار Bot API است و هیچ رباتی نمی‌تواند از آن فرار کند.

**پس با SST سراغ اطلاعات حساس نروید** - کلید خصوصی `cat` نکنید، رمز دیتابیس تایپ نکنید، روی سرور پروडاکشن `env` نزنید. برای این کارها SSH هست.

### رمزنگاری در مسیر انتقال

| مسیر | محافظت |
|---|---|
| تلگرام ← سرور شما (webhook) | حداقل TLS 1.2 (نسخه‌های ۱.۰ و ۱.۱ رد می‌شوند)، گواهی Let's Encrypt با تمدید خودکار شبانه |
| سرور شما ← تلگرام (polling) | TLS با تأیید کامل زنجیره گواهی و نام دامنه |
| حالت self-signed | RSA-2048 / SHA-256، و گواهی عمومی با `setWebhook` به تلگرام آپلود می‌شود تا واقعاً معتبر شناخته شود |

### چهار لایه احراز هویت

در حالت Webhook سرور شما یک پورت روی اینترنت باز دارد. برای اینکه آن پورت به یک شل رایگان برای کل اینترنت تبدیل نشود، **هر** درخواست باید از هر چهار لایه رد شود:

| # | لایه | جزئیات |
|---|---|---|
| ۱ | **IP مبدأ** | باید داخل رنج‌های رسمی تلگرام باشد: `149.154.160.0/20` و `91.108.4.0/22` |
| ۲ | **مسیر مخفی** | وب‌هوک روی `/<۳۲ کاراکتر تصادفی>` است - ۱۲۸ بیت آنتروپی، نه `/` |
| ۳ | **`secret_token`** | هدر `X-Telegram-Bot-Api-Secret-Token` باید با یک کلید ۶۴ کاراکتری (۲۵۶ بیت) بخواند؛ مقایسه با `hmac.compare_digest` انجام می‌شود تا زمان پاسخ چیزی لو ندهد |
| ۴ | **هویت کاربر** | آپدیت باید از `user_id` شما باشد، **و در چت خصوصی خودتان** (`chat.id == user_id` و نوع `private`) |

هر درخواستی که رد شود یک **۴۰۴ خالی** می‌گیرد - نه ۴۰۳، نه پیام خطا، نه بنر سرور. اسکنر هیچ سرنخی از آنچه پشت این پورت است نمی‌گیرد.

لایه ۴ حتی اگر بقیه بیفتند مهم است: مهاجمی که به هر شکلی کلید مخفی را به دست آورده، باز هم نمی‌تواند خروجی را به چت خودش بفرستد، چون `chat_id` با آیدی خودِ شما مقایسه می‌شود نه با چیزی که در درخواست آمده.

ربات در حالت webhook **بدون کلید مخفی و مسیر مخفی اصلاً بالا نمی‌آید**. هیچ مسیر «برگرد به اعتماد کردن به بدنهٔ درخواست» وجود ندارد - دقیقاً همان چیزی که در نسخه ۱.x فاجعه ساخته بود.

### محافظت روی دیسک

| مسیر | مجوز |
|---|---|
| `/opt/sst` | `0700` |
| `/opt/sst/config.json` | `0600` - توکن ربات + کلید وب‌هوک |
| `/opt/sst/certs/*.pem` | `0600` |
| یونیت systemd | `UMask=0077` |

اگر `config.json` برای دیگران قابل خواندن باشد، SST موقع بالا آمدن هشدار می‌دهد. کلیدها **هیچ‌وقت در لاگ نوشته نمی‌شوند** - آدرس وب‌هوک با مسیر سانسورشده لاگ می‌شود.

### محافظت‌های دیگر

- حجم بدنهٔ درخواست به ۲ مگابایت محدود است؛ JSON خراب قبل از هر پردازش معناداری رد می‌شود
- سرور HTTP خودش را `nginx` معرفی می‌کند و هیچ‌وقت نسخهٔ پایتون را لو نمی‌دهد
- پاسخ `200 OK` **قبل از** اجرای دستور به تلگرام داده می‌شود، پس یک دستور کند هیچ‌وقت باعث retry و اجرای دوباره نمی‌شود
- `drop_pending_updates` موقع استارت - دستورهایی که موقع خاموشی ربات صف شده‌اند دور ریخته می‌شوند، نه اینکه دوباره اجرا شوند
- سشن‌های بی‌کار به‌صورت پیش‌فرض بعد از ۳۰ دقیقه بسته می‌شوند
- بستن سشن **کل session پروسه‌ها** را جارو می‌کند، پس job‌های بک‌گراند و `disown`شده نمی‌توانند زنده بمانند
- هر درخواست ردشده شمرده و لاگ می‌شود؛ `/status` تعداد کل را نشان می‌دهد

### چیزهایی که SST محافظت نمی‌کند

- **هک شدن اکانت تلگرام شما** - یعنی دسترسی کامل به سرور، و تنها دفاع شما تأیید دو مرحله‌ای است
- **لو رفتن `config.json`** - هر کسی که توکن را داشته باشد می‌تواند خودش را جای ربات شما جا بزند
- **خودِ تلگرام** - به بخش رمزنگاری سرتاسری بالا نگاه کنید
- **خودتان** - ربات عمداً با دسترسی root اجرا می‌شود و هیچ لیست سفیدی برای دستورات ندارد

اگر می‌خواهید دامنهٔ خسارت را کم کنید، سرویس را با یک کاربر غیر root اجرا کنید و دستورهای خاص را از طریق `sudoers` بدهید - کافی است `User=` را در `/etc/systemd/system/sst-bot.service` عوض کنید.

## 🧩 چطور کار می‌کند

```
تلگرام ──► webhook / polling ──► لایه‌های احراز هویت ──► handle_update()
                                                              │
                                                              ▼
                                                  Session (یکی برای هر کاربر)
                                       ┌──────────────────────┴──────────────────────┐
                                       │  bash --login روی یک PTY واقعی              │
                                       │  با session و controlling tty مخصوص خودش    │
                                       └──────────────────────┬──────────────────────┘
                                                              │ یک thread خوانندهٔ واحد
                                                              ▼
                                              terminal.py - مدل صفحهٔ VT100
                                                              │
                                                              ▼
                                          آپدیت‌های throttle‌شدهٔ editMessageText
```

دو نکته دربارهٔ طراحی:

`terminal.py` یک شبیه‌ساز صفحه است، نه پاک‌کنندهٔ ANSI. یک شبکهٔ کاراکتری با مکان‌نما، ناحیهٔ اسکرول، صفحهٔ جایگزین و scrollback مدل می‌کند، برای همین `top` و `nano` یک تصویر درست می‌سازند نه دیواری از کدهای escape. کاملاً با کتابخانهٔ استاندارد نوشته شده.

پایان دستور خوانده می‌شود، نه حدس زده. `os.tcgetpgrp()` روی master پی‌تی‌وای می‌گوید ترمینال دست شل است یا دست یک بچه‌پروسه. وقتی شل آن را پس گرفت - به‌صورت پیوسته، تا حلقه‌هایی که ترمینال را رد و بدل می‌کنند ما را گول نزنند - دستور واقعاً تمام شده. به همین دلیل یک build بیست‌دقیقه‌ای همچنان استریم می‌شود به‌جای اینکه بعد از دو ثانیه سکوت «تمام» اعلام شود.

## ⚙️ تنظیمات پیشرفته (`config.json`)

| کلید | پیش‌فرض | توضیح |
|---|---|---|
| `cols` / `rows` | `80` / `55` | ابعاد ترمینال. ۵۵ خط یک پیام تلگرام را پر می‌کند؛ خیلی بیشتر از ۶۰ بریده می‌شود |
| `session_timeout` | `1800` | ثانیه بی‌کاری تا بسته شدن شل (`0` = هرگز) |
| `edit_interval` | `1.2` | فاصلهٔ بین آپدیت‌های پیام - کمترش خطر rate limit تلگرام دارد |
| `max_stream` | `300` | حداکثر ثانیه استریم یک دستور قبل از نمایش «هنوز در حال اجرا» |
| `idle_stop` | `2.0` | تشخیص از روی سکوت؛ فقط وقتی استفاده می‌شود که pgid پی‌تی‌وای خوانده نشود |
| `ip_filter` | `true` | بررسی رنج IP تلگرام - اگر پشت پروکسی معکوس هستید `false` کنید |
| `tls` | `true` | اگر nginx/Caddy جلوتر TLS را ترمینیت می‌کند `false` کنید |
| `bind` | `0.0.0.0` | آدرس گوش دادن |
| `shell` | `["bash","--login"]` | شل مورد استفاده |
| `miniapp` | `true` | سرو کردن مینی‌اپ |
| `webapp_key` | تولید می‌شود | کلید لینک مرورگر معمولی |
| `log_level` | `INFO` | `DEBUG`، `INFO`، `WARNING`، `ERROR` |

بعد از هر تغییر: `sst restart`

## 🛠️ مشکل‌یابی

| مشکل | راه‌حل |
|---|---|
| ربات جواب نمی‌دهد | `sst logs` - اگر خط `rejected` می‌بینید، احراز هویت رد می‌شود |
| `sst webhook` خطای SSL می‌دهد | گواهی self-signed دارید و دامنه به این سرور resolve نمی‌شود |
| تلگرام به پورت نمی‌رسد | Cloudflare را DNS-only کنید؛ `ss -lntp \| grep 88` و فایروال را چک کنید |
| دستور زودتر تمام می‌شود | دکمهٔ ⟳ Refresh را بزنید - شل هنوز در حال اجراست |
| خروجی شکسته یا تنگ است | `sst config` → `cols` / `rows` را تنظیم کنید |
| از یک لیست بلند فقط خطوط آخر دیده می‌شود | دکمهٔ 🔼 Scroll back، یا `/full` و مینی‌اپ |
| دکمهٔ مینی‌اپ نیست | حالت webhook با گواهی معتبر لازم است؛ `/app` بزنید تا دلیلش را بگوید |
| مینی‌اپ سفید باز می‌شود | گواهی self-signed است، یا پورت از گوشی شما در دسترس نیست |
| بعد از ری‌بوت بالا نمی‌آید | `journalctl -u sst-bot -n 50 --no-pager` |
| هشدار rate limit در لاگ | `edit_interval` را بیشتر کنید |
